## Evidencias del cierre

El smoke directo del origen validó:

- `/up` HTTP 200;
- `/admin/login` HTTP 200;
- `/mi-dia` HTTP 302 sin sesión;
- `/buscar` HTTP 302 sin sesión;
- `/estado-recuperacion` HTTP 302 sin sesión.

El comando `central:db-health` reportó 4 conexiones de 120
(3.3 %) inmediatamente después del despliegue y un máximo histórico
de 81 conexiones. Ese máximo pertenece al servidor completo y no
atribuye causa a CENTRAL.

El monitor externo de MariaDB quedó activo con estado NORMAL y conserva
el contador histórico de 13 rechazos por límite registrados antes del
cambio de capacidad.

## Riesgo residual principal

La deuda más visible después de 2.38.4 es frontend: varias vistas Blade
siguen conteniendo grandes bloques de CSS/JS embebidos. Esto no impide
la operación ni el CSP progresivo actual, pero dificulta endurecer
`script-src` / `style-src`, aumenta duplicación y vuelve más costosa
la evolución visual.

El siguiente frente se denomina **2.39 — Consolidación de assets FRONT**.
Antes de modificar el pipeline de producción se debe verificar
disponibilidad de Node/npm en cPanel y definir si los assets Vite se
construyen en servidor o se publican como artefacto inmutable.
