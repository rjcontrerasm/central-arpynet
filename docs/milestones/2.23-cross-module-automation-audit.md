# 2.23 — Automatización cross-module

## Objetivo

Conectar señales de un módulo de CENTRAL con efectos seguros en otro módulo, manteniendo autorización por organización, deduplicación, confirmación humana y undo.

## Auditoría

La infraestructura necesaria ya existe:

- señales en tareas, proyectos, servicios, obligaciones y esperas;
- modos `preview`, `confirmation` y `automatic`;
- fingerprint y deduplicación por regla/sujeto/estado;
- confirmación humana;
- `GlobalUndoService`;
- aislamiento por organización.

La brecha funcional es que las automatizaciones actuales solo mutan su propio dominio o crean notificaciones internas; no crean todavía una entidad operativa en otro módulo.

## Diseño de cierre

La primera capacidad cross-module queda limitada a creación de `Task` en modo `confirmation`.

Acciones nuevas:

- `project.create_task`;
- `service.create_task`;
- `obligation.create_task`.

Triggers habilitados inicialmente:

- `project.no_next_action`;
- `project.blocked`;
- `service.conformity_ready`;
- `service.invoice_overdue`;
- `obligation.due_soon`.

## Salvaguardas

- no existe modo automático para estas acciones;
- la tarea se crea únicamente después de confirmación humana;
- el usuario confirmante debe tener permiso de escritura en la organización;
- el origen y la tarea deben pertenecer a la misma organización;
- se revalida la señal antes de crear la tarea para evitar ejecutar una decisión `stale`;
- las tareas provenientes de proyecto quedan vinculadas mediante `project_id`;
- servicios y vencimientos conservan referencia mediante `external_system` / `external_id`;
- `source = automation`;
- `GlobalUndoService::rememberTaskCreated()` permite deshacer;
- el fingerprint existente evita repetir el mismo run mientras el origen no cambie;
- no hay red ni canales externos.

## Validación requerida

La suite específica debe demostrar:

- preview sin creación de tarea;
- ejecución de regla en modo confirmación sin creación anticipada;
- confirmación explícita antes de crear;
- misma organización y vínculo al proyecto cuando corresponda;
- referencia externa para servicios y obligaciones;
- deduplicación;
- rechazo sin efectos;
- undo;
- protección `stale`;
- bloqueo para usuarios `viewer`;
- rechazo del modo `automatic` para creación cross-module.
